# StackOverflow Oracle 问题聚类基准实验报告

## 1. 实验目的

建立一套简单、可复现的文本聚类基准方案，为后续文本增强、参数搜索和相似问题识别提供对照。基准方案只使用问题标题与正文，不引入标签、回答内容或领域规则。

| 项目 | 配置 |

| 数据集 | StackOverflow Oracle Database Questions |
| 原始记录数 | 152,758 |
| 输入格式 | JSONLines |
| 实验抽样 | 10%，随机种子 42 |
| 实际样本数 | 15,344 |
| Spark | 2.0.0 |
| Hadoop | 2.7 |
| Python | 2.7 |
| 集群 | 1 个 Master、2 个 Worker |
| Executor | 2 个，每个 2 核、4 GB |

## 3. 基准方法

```text
JSONLines 数据
→ HTML 清洗
→ 拼接 title + body
→ 小写化与特殊字符清理
→ Tokenizer
→ StopWordsRemover
→ CountVectorizer
→ IDF
→ L2 Normalizer
→ KMeans
```

核心参数：

| 参数 | 数值 |
| --- | ---: |
| K | 50 |
| max_features | 5,000 |
| min_df | 5 |
| max_iter | 30 |
| seed | 42 |

## 4. 评价指标

Spark 2.0 不包含 `ClusteringEvaluator`，因此本实验不把固定的 `0.0` 当作轮廓系数。基准程序使用以下真实可计算指标：

- **WSSSE**：样本到所属聚类中心的平方距离之和，越低越好，仅适合在相同数据和特征口径下比较。
- **最大簇占比**：判断是否出现大量样本坍缩到同一簇。
- **簇大小变异系数（CV）**：衡量簇规模不均衡程度，越低越均衡。
- **归一化簇熵**：衡量样本在各簇间的分散程度，越接近 1 越均衡。
- **运行时间**：评价方案在当前集群上的计算成本。

- `cluster_summary`：各聚类的问题数量；
- `top_questions_per_cluster`：每个聚类中分数最高的 10 个问题。

## 6. 结果分析

基准方案完成了端到端聚类，但质量存在明显上限。最大簇包含 5,874 条问题，占全部样本的 38.28%，而最小簇只有 1 条；簇大小 CV 达到 2.6609，归一化簇熵仅为 0.7227，说明簇规模严重不均衡。最大簇中的示例问题主题跨度较大，表明只使用标题与正文的通用 TF-IDF 特征，容易受 `oracle`、`sql` 等领域高频词影响。

运行时间方面，KMeans 训练约占总时间的 77.2%，是当前流程的主要性能瓶颈。日志还提示输入特征没有直接缓存，因此后续优化可通过缓存特征数据减少重复计算。

## 7. 基准结论

本实验建立了可复现的 TF-IDF + KMeans 流程，在 Spark 集群上成功处理 15,344 条样本，并生成完整的聚类结果。实验同时暴露了簇分布不均衡和训练耗时较长两个主要问题。因此，该方案适合作为后续优化的对照组，但不能直接作为最终高质量聚类方案。

## 8. 后续优化路线

| 基准问题 | 优化方向 | 对照指标 |
| --- | --- | --- |
| 通用高频词干扰 | 增加 Oracle 领域停用词 | 最大簇占比、簇熵 |
| 标题信息权重不足 | 标题重复加权并加入 tags | WSSSE、人工主题一致性 |
| 文本信息不足 | 加入高分回答文本 | 重复问题召回率 |
| K 固定为 50 | 对 K=20/30/50/80 做参数搜索 | WSSSE、CV、运行时间 |
| 训练重复计算 | 缓存处理后的特征 DataFrame | KMeans 训练时间 |
| 聚类不等于去重 | 簇内计算余弦相似度 | 重复候选数量与准确率 |

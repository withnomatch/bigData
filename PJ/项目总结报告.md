# StackOverflow Oracle 问题聚类与去重项目总结报告

## 一、项目亮点

本项目的核心目标不是单纯完成文本聚类，而是围绕“重复问题识别”建立一套可验证、可比较、可复现的实验流程。相比只看聚类轮廓系数或簇分布，本项目进一步引入人工标注数据，对每个优化方案进行真实去重效果检验。

主要亮点如下：

- 构建了 300 对人工标注评测数据，包含 100 对重复问题、100 对相关但不重复问题、100 对不相关问题。
- 将 300 对标注数据作为统一去重评测集，所有优化过程都必须回到这批数据上计算 Precision、Recall、F1 和 Candidate Recall。
- 设计了“固定 10% 随机样本 + 标注数据涉及问题”的统一实验样本，保证每个人使用完全相同的数据输入。
- 区分“聚类候选召回”和“最终重复判定”两个阶段，使用 Candidate Recall 分析真实重复问题是否被聚到同一簇。
- 在特征层面不仅使用 TF-IDF，还规划了标题加权、标签加权、答案文本融合、Word2Vec 和加权 Word2Vec 等语义特征处理方法。
- 在算法层面对比 KMeans、BisectingKMeans、小簇合并和簇标签生成，关注聚类结构对去重召回的影响。
- 在执行层面对 K 值、初始化方式、距离度量、最大迭代次数和随机种子稳定性进行统一实验。
- 新增 Spark 输出评测脚本，可直接读取每个人的聚类输出和重复候选输出，再用 300 对标注数据统一验收。

## 二、项目背景与任务定义

StackOverflow 中存在大量主题相近、表达不同甚至本质重复的问题。对于 Oracle 数据库相关问题，如果能将重复问题识别出来，可以减少用户重复检索成本，也能帮助平台聚合已有答案。

本项目将任务拆成两个层次：

1. 聚类候选召回：先将相似问题聚到同一簇，缩小后续比较范围。
2. 簇内重复判定：在同一簇内计算问题对相似度，高于阈值则判定为疑似重复。

因此，聚类本身不是最终答案。真正的去重结果来自：

```text
同簇问题对
→ 余弦相似度计算
→ 阈值筛选
→ duplicate_candidates
```

## 四、统一评测方法

每个人跑完实验后，都要用同一套 300 对标注数据做去重检验。

评测逻辑如下：

```text
读取 300 对标注问题
→ 查询每个 question_id 的 cluster_id
→ 判断两个问题是否同簇
→ 查询是否出现在 duplicate_candidates 中
→ 统计 TP / FP / FN / TN
→ 计算 Precision / Recall / F1 / Candidate Recall
```

核心指标：

| 指标 | 含义 |
| --- | --- |
| Precision | 被判为重复的问题对中，真实重复的比例 |
| Recall | 真实重复问题对中，被成功识别的比例 |
| F1 | Precision 和 Recall 的综合指标 |
| Candidate Recall | 真实重复问题对中，被聚到同一簇的比例 |

其中 Candidate Recall 非常关键，因为如果真实重复问题没有被聚到同一簇，后续相似度阈值再怎么调整也无法召回。

统一评测脚本：

```text
evaluate_dedup_from_spark_outputs.py
```

### 6.4 基线结果分析

基线 Precision 达到 0.75，说明被系统输出为重复的问题对中，大部分确实是重复问题，误报较少。但 Recall 只有 0.03，说明真实重复问题大量没有被最终识别出来。

Candidate Recall 为 0.42，说明 100 对真实重复问题中，有 42 对被聚到了同一簇。这表明基线的主要瓶颈有两个：

1. 聚类候选召回不足：仍有 58 对真实重复问题没有进入同一簇，后续无法比较。
2. 同簇后阈值筛选偏严格：42 对同簇真实重复中，最终只有 3 对进入 duplicate_candidates。

因此，后续优化不能只调相似度阈值，还需要重点提升特征表示和聚类结构，使真实重复问题更容易进入同一簇。

## 十三、当前结论

当前 A 基线已经完成，并且建立了可复用的评测链路。结果说明：

- 数据链路已经打通：固定样本中包含全部 300 对标注问题，评测时 `missing_assignment=0`。
- 基线误报较少：Precision 为 0.7500。
- 基线召回明显不足：Recall 为 0.0300，F1 为 0.0577。
- 聚类候选阶段仍有改进空间：Candidate Recall 为 0.4200。

后续优化重点应放在：

1. 提高真实重复问题进入同一簇的比例。
2. 使用语义特征减少表达差异导致的漏报。
3. 调整 K 值和聚类结构，平衡簇规模与候选召回。
4. 在验证集上选择阈值，避免只用固定 0.55 阈值导致召回过低。

# StackOverflow 问题去重聚类：实验思路与成员 PPT 数据

## 1. 总体实验目标

任务不是单纯把问题分成若干主题，而是：

```text
问题文本
-> 文本清洗与特征表示
-> 聚类缩小候选范围
-> 同簇问题计算余弦相似度
-> 输出疑似重复问题对
```

聚类负责候选召回，余弦阈值负责重复判定。因此需要同时报告：

- 聚类质量：Silhouette、WSSSE/WCSS、簇内语义一致性；
- 聚类分布：最大簇占比、最小簇、标准差、CV、小簇/单点簇；
- 运行性能：特征时间、训练时间、总时间；
- 最终去重：Precision、Recall、F1、PR-AUC、Candidate Recall、Precision@K。

## 2. 统一实验口径

| 项目     | 统一设置                                    |
| ------ | --------------------------------------- |
| 数据集    | StackOverflow Oracle Database Questions |
| 原始记录数  | 152,758                                 |
| 聚类实验抽样 | 10%，随机种子 42                             |
| 实际样本数  | A/E/F：15,441；D：15,344                   |
| 默认 K   | 50，B 单独搜索 40-60                         |
| 基准特征   | title + body，TF-IDF，L2 归一化              |
| 基准参数   | vocabSize=5000，minDF=5，maxIter=30       |
| 集群     | Spark，1 Master + 2 Workers              |
| 去重测试集  | 300 对：100重复、100相关不重复、100不相关             |

注意：

1. Spark 2.0 没有官方 `ClusteringEvaluator`。自定义或抽样轮廓必须写成
   “抽样轮廓”或“中心近似轮廓”。
2. 不同特征空间下的 WCSS 数值不能直接比较，例如 TF-IDF 与 Word2Vec 的
   WCSS 只适合各自内部参考。
3. 标准轮廓系数范围为 `[-1,1]`。C 报告中的 `-2.10/-2.15` 不是合法标准

### A-4 PPT：300 对局部去重评测

测试集：

| 标签     | 数量  | 来源                                    |
| ------ | ---:| ------------------------------------- |
| 重复     | 100 | Stack Overflow `Possible Duplicate`链接 |

300 对全部由现有数据组合得到：

- 重复：正文包含 `Possible Duplicate`链接，且链接两端都存在于当前数据集；
- 相关但不重复：同一基线簇，标题Jaccard为0.28～0.72，并共享错误码或至少
  两个有效关键词，排除官方重复关系后取相似度最高的100对；
- 不相关：来自不同基线簇，不共享错误码，标题Jaccard不高于0.02，随机抽取
  100对；
- 所有抽样固定随机种子42，300对互不重复，共涉及542个问题；
- 重复正例具有平台链接证据，后两类属于机器辅助初审，正式金标准需要第二人
  复核。

实验：`title*3 + body + tags*2 -> TF-IDF -> L2 -> 球面KMeans(K=50)`；
同簇且余弦相似度不低于 0.55 判为重复。

评测范围说明：

- 本实验只对300对涉及的542个问题重新构建特征并聚类，不是对152,758条
  全量数据重新聚类后的最终结果；
- 数据人为平衡为三类各100对，真实环境中的重复比例通常更低；
- 后两类负例尚待第二位成员复核；
- 阈值0.55尚未通过独立验证集选择，因此当前结果属于固定阈值下的初步评测；
- 本轮脚本未记录各阶段运行时间，PPT中不要补写估算值。

### D-2 PPT：实测结果

| 指标      | TF-IDF      | Word2Vec   | TF-IDF加权Word2Vec |

| 抽样轮廓系数  | 0.0189      | 0.1091     | **0.1376**       |

| 非空簇     | 50          | 50         | 50               |

### D-3 PPT：结论与语义分析

- TF-IDF：最快、关键词可解释，但出现 32.86% 巨型簇；
- Word2Vec：语义一致性最高，但关键词中出现 `want/without/also` 等通用词，
  可解释性较弱；
- 加权 Word2Vec：轮廓最高、分布最均衡，但耗时最大；
- 推荐综合方案：TF-IDF加权Word2Vec；
- 推荐工程方案：若强调效率，使用纯 TF-IDF；若强调语义召回，使用加权
  Word2Vec。

注意：三种特征空间不同，WCSS 不能直接据此宣布 Word2Vec 胜出。

| K 值       | K=60；统一对比可保留50                    | B 的轮廓最高、Inertia最低      |
| TF-IDF 参数 | vocabSize=3000、minDF=3、maxDF=0.90 | C 的64组实测最优             |
| 特征表示      | TF-IDF加权Word2Vec                  | D 的轮廓最高、分布最均衡          |
| 聚类结构      | BisectingKMeans                   | E 的最大簇、CV和小簇数更好        |
| 执行参数      | random + cosine/L2 + iter20       | F01 综合最好               |
| 去重阈值      | 当前0.55，仅为基线                       | Precision高但Recall仅0.18 |

建议最终组合实验：

```text
C 的最佳TF-IDF参数：3000/3/0.90
-> D 的 TF-IDF加权Word2Vec
-> B 的 K=60
-> E 的 BisectingKMeans
-> F 的余弦表示与合理迭代参数
-> 同簇余弦相似度阈值搜索
-> 300 对标注集计算 Precision/Recall/F1
```

但不要直接假设各成员的单项最优拼起来一定是全局最优，最终组合必须再跑一次
端到端实验。

## 10. 建议 PPT 顺序

1. A：任务背景、数据集、系统架构；
2. A：基准流程、基准指标、问题分析；
3. B：K=40-60 曲线与 K 选择；
4. C：64组TF-IDF参数实测结果与预处理优化设计；
5. D：三种特征表示对比与语义案例；
6. E：K-Means/BisectingKMeans与后处理；
7. F：初始化、距离、迭代和随机种子；

10. B：总结、局限与展望。

## 11. 最终汇报的三个核心结论

1. 基准 TF-IDF+KMeans 可以运行，但存在巨型簇和语义召回不足；
2. Word2Vec语义特征、BisectingKMeans和合理的余弦执行参数能明显改善簇分布；
3. 在542个问题组成的局部平衡测试集上，固定阈值下Precision=0.7826、
   Recall=0.18；下一阶段重点不是继续压低WSSSE，而是提高Candidate Recall，
   并使用独立验证集选择阈值后再进行全量验证。

# 项目收尾清单、分工与报告框架

本文档用于项目最后阶段的统一推进：所有优化过程必须使用 `annotation/dedup_pairs_300_reviewed.csv` 中的 300 条标注问答对重新做去重评测，最后只按同一套标注数据和同一套指标选择最优方案。

## 一、未完成清单

- [ ] 处理争议标注，形成最终版 `dedup_pairs_300_reviewed.csv`；如有第二标注者，补充一致率和 Cohen's Kappa。
- [ ] 固定验证集/测试集划分：建议按标签分层拆分为 150 对验证集、150 对测试集，随机种子统一为 42。
- [ ] 把现有各成员优化方案全部接入统一评测入口，输出相同字段的指标文件。
- [ ] 对每个优化过程重新测去重效果，包括 Candidate Recall、Precision、Recall、F1、PR-AUC、Precision@K、各类别 Support 和混淆矩阵。
- [ ] 只在验证集上选择 K 值、相似度阈值、特征参数、聚类算法和执行参数。

- [ ] 绘制统一对比图表：PR 曲线、阈值-F1 曲线、Candidate Recall 对比、运行时间对比。

## 执行流程

1. 标注数据确认：以 `annotation/dedup_pairs_300_reviewed.csv` 为唯一人工标注来源。
2. 固定实验样本：生成“10% 随机样本 + 300 对标注数据涉及的全部问题”，并去重保存为统一输入。
3. 数据拆分：对 300 对标注数据生成固定验证集和测试集，保存拆分文件，后续实验不得临时重抽样。
4. 基线重跑：先在统一固定样本上跑当前基线方案，再用 300 对标注数据回查去重效果。
5. 单项优化重测：B、C、D、E、F 的单项优化都必须读取同一份固定样本，不能各自重新抽样。
6. 组合优化重测：按“B 的 K 值 -> C/D 的特征 -> F 的执行参数 -> E 的聚类结构和后处理”逐步组合。
7. 最优方案选择：优先看测试集 F1 和 PR-AUC，同时约束 Candidate Recall、误报案例和运行时间。
8. 全量流程验证：最优配置回到全量数据流程中运行，再用 300 对标注数据回查去重效果。

固定样本生成命令示例：

```bash
spark-submit create_fixed_sample.py \
  --input hdfs://node5:9000/user/root/data/oracle_database_questions_jsonlines.json \
  --annotation-pairs hdfs://node5:9000/user/root/data/dedup_pairs_300_reviewed.csv \
  --output hdfs://node5:9000/user/root/data/fixed_eval_sample_10pct_plus_300 \
  --ratio 0.1 \
  --seed 42
```

之后所有实验统一使用：

```bash
--input hdfs://node5:9000/user/root/data/fixed_eval_sample_10pct_plus_300
--sample-ratio 1.0
```

可以。这个项目最合理的实验流程应该是 **“先确定评测集和基线，再逐层优化，最后组合最优方案统一重测”**。核心原则是：**每一步实验都不能只看自己的聚类指标，必须把结果拿到 300 条标注数据上测去重效果。**

**整体实验测试流程**

```
原始数据
  ↓
基线实验 A
  ↓
300 条标注数据评测基线
  ↓
B：K 值实验
  ↓
固定最佳 K
  ↓
C / D：特征表示实验
  ↓
固定最佳特征方案
  ↓
E：聚类算法与后处理实验
  ↓
固定最佳聚类结构
  ↓
F：执行参数实验
  ↓
固定最佳运行参数
  ↓
组合最优方案
  ↓
300 条标注数据最终测试
  ↓
报告与 PPT
```

**第 1 步：先跑基线实验 A**

基线方案：

```
原始 JSONLines 数据
→ HTML 清洗
→ title + body 文本
→ TF-IDF
→ KMeans
→ 输出聚类结果
→ 同簇内计算相似度
→ 生成疑似重复问题对
```

基线要输出：

- 聚类分配结果
- 每个簇大小
- 最大簇占比
- 簇大小 CV
- 运行时间
- 同簇内重复候选对

然后立刻用 300 条标注数据测：

- Candidate Recall
- Precision
- Recall
- F1
- PR-AUC
- Precision@10 / 20 / 50 / 100
- 混淆矩阵

这一步的结果就是后面所有优化的对照组。

**第 2 步：B 做 K 值实验**

B 不应该直接追求聚类看起来均匀，而是要测试：

```
K = 40, 45, 50, 55, 60
```

每个 K 都要完整走：

```
TF-IDF
→ KMeans
→ 生成候选重复对
→ 用 300 条标注数据评测
```

B 的输出是：

```
不同 K 值下的去重效果表
```

重点看：

- Candidate Recall 是否提高
- F1 是否提高
- 误报是否变多
- 运行时间是否可接受

然后选出一个推荐 K，比如：

```
最佳 K = 45 或 50 或 55
```

后续 C、D、E、F 都应该优先使用 B 选出的 K，而不是继续默认 K=50。

**第 3 步：C 做 TF-IDF 和预处理优化**

C 要在 B 选出的最佳 K 基础上继续做。

流程是：

```
使用 B 推荐的 K
→ 测不同文本预处理方式
→ 测不同 TF-IDF 参数
→ 每组结果都用 300 条标注数据评测
```

可以测试：

```
方案 C1：title + body
方案 C2：title 加权 + body
方案 C3：title + body + tags
方案 C4：title 加权 + body + tags 加权
方案 C5：去停用词 / 保留错误码 / 保留 SQL 关键词
```

每个方案输出：

- Candidate Recall
- Precision
- Recall
- F1
- PR-AUC
- 典型误报案例
- 典型漏报案例

C 完成后，应该给出：

```
最佳 TF-IDF / 预处理方案
```

后续 D、E、F 都应该基于 C 的最佳文本处理方案继续做。

**第 4 步：D 做 Word2Vec / 语义特征实验**

D 要和 C 对比，不能孤立做。

D 的实验应该使用：

```
B 推荐的 K
+ C 推荐的预处理方式
```

然后比较：

```
D1：TF-IDF
D2：Word2Vec
D3：TF-IDF + Word2Vec
D4：加权 Word2Vec
```

每个方案都要重新跑：

```
特征构建
→ 聚类
→ 候选生成
→ 300 条标注数据评测
```

D 的重点不是只看聚类分布，而是看：

- Candidate Recall 有没有提升
- 漏报是否减少
- 相关但不重复的问题是否被误判为重复
- 运行时间是否明显变长

如果 Word2Vec 提高了 Candidate Recall，但 Precision 降低，就要报告清楚：

```
语义特征召回更强，但误报风险更高
```

D 完成后，输出：

```
最佳特征方案：继续用 TF-IDF，还是 TF-IDF + Word2Vec
```

**第 5 步：E 做聚类算法和后处理实验**

E 应该在前面已经确定的基础上做：

```
B 的最佳 K
+ C/D 的最佳特征方案
```

然后对比：

```
E1：KMeans
E2：BisectingKMeans
E3：KMeans + 小簇合并
E4：BisectingKMeans + 小簇合并
E5：聚类标签生成
```

E 的重点指标是：

- Candidate Recall
- 最大簇占比
- 簇大小 CV
- 小簇数量
- 最终 F1

这里有一个关键逻辑：

```
聚类阶段决定 Candidate Recall
相似度阈值阶段决定 Precision / Recall 平衡
```

如果真实重复问题被分到不同簇，后面相似度再好也找不回来。所以 E 要重点回答：

```
哪种聚类结构最能把真实重复问题放进同一个簇？
```

E 完成后，输出：

```
最佳聚类算法 + 是否需要小簇合并
```

**第 6 步：F 做执行参数实验**

F 不应该最早做，因为执行参数要依赖前面的最终结构。

F 应该基于：

```
B 最佳 K
+ C/D 最佳特征
+ E 最佳聚类算法
```

测试：

```
初始化方式
距离度量
maxIter
随机种子
多次运行稳定性
```

F 的输出重点是：

- 指标是否稳定
- 运行时间是否下降
- 不同随机种子下 F1 波动
- 推荐最终执行参数

比如最后给出：

```
seed = 42
maxIter = 20
distance = cosine 等价特征
initMode = random 或 k-means||
```

**第 7 步：组合最优方案**

当前面所有单项实验完成后，A 负责整合。

组合顺序应该是：

```
基线
→ 加入 B 的最佳 K
→ 加入 C/D 的最佳特征
→ 加入 E 的最佳聚类结构
→ 加入 F 的最佳执行参数
→ 加入最终相似度阈值
```

每加一步，都要用 300 条标注数据测一次。

最终对比表应该长这样：

| 方案       | K   | 特征     | 聚类算法   | 后处理 | 阈值   | Candidate Recall | Precision | Recall | F1  |
| -------- | --- | ------ | ------ | --- | ---- | ---------------- | --------- | ------ | --- |
| Baseline | 50  | TF-IDF | KMeans | 无   | 0.55 | ...              | ...       | ...    | ... |
| + B      | 最佳K | TF-IDF | KMeans | 无   | 0.55 | ...              | ...       | ...    | ... |
| + C/D    | 最佳K | 最佳特征   | KMeans | 无   | 0.55 | ...              | ...       | ...    | ... |
| + E      | 最佳K | 最佳特征   | 最佳聚类   | 有/无 | 0.55 | ...              | ...       | ...    | ... |
| + F      | 最佳K | 最佳特征   | 最佳聚类   | 有/无 | 最佳阈值 | ...              | ...       | ...    | ... |

**最终推荐流程一句话版**

先用 A 跑基线并用 300 条数据测出初始效果；再让 B 选 K；然后 C/D 在最佳 K 上选特征；接着 E 在最佳特征上选聚类算法和后处理；最后 F 在最终结构上调执行参数和稳定性；每一步都必须重新用 300 条标注数据测去重效果，最后 A 把所有单项最优组合起来，再做一次最终统一测试。

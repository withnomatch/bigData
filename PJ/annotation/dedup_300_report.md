# 300对问题标注与去重实验报告

## 数据构成

- 总问题对：300
- 重复：100（Stack Overflow正文中的Possible Duplicate链接）
- 相关但不重复：100（同簇、高标题相似度困难负例初审）
- 不相关：100（跨簇、低标题相似度保守负例初审）
- 涉及问题数：542

其中重复标签有平台链接证据；两类负例属于机器辅助初审，正式报告前仍需第二位
标注者逐对复核。

## 数据来源与筛选方法

300 对问题全部来自项目已有数据，没有引入外部问题：

- 问题正文与标题来自 `oracle_database_questions_jsonlines.json`；
- 基线聚类编号来自 `local_test_output/assignments.csv`；
- 最终 300 对涉及 542 个不同问题；
- 所有问题对均去重，固定随机种子为 `42`，保证结果可以复现。

### 重复问题：100 对

1. 遍历现有 JSONLines 数据中的问题正文；
2. 查找正文中的 `Possible Duplicate`提示；
3. 从正文链接中提取目标 Stack Overflow `question_id`；
4. 要求源问题和目标问题都存在于当前 Oracle 数据集；
5. 去除自身链接以及顺序相反的重复问题对；
6. 固定随机种子 42，从有效官方重复关系中抽取 100 对。

这组不是根据标题相似度推测得到的，而是使用当前数据正文中保留的平台重复指向
作为正例证据。

### 相关但不重复：100 对

1. 使用现有基线聚类结果，将问题按照 `cluster`分组；
2. 只在同一聚类内部生成候选问题对；
3. 要求标题具有中高相似度，Jaccard相似度范围为 `0.28～0.72`；
4. 同时要求共享 Oracle/PLSQL 错误码，或者共享至少两个有效标题关键词；
5. 排除所有已经具有官方 `Possible Duplicate`关系的问题对；
6. 按标题相似度从高到低选择前 100 对。

这组用于构造困难负例：两个问题属于相同技术主题，甚至拥有相同错误码，但输入
条件、运行环境、操作对象或具体诉求可能不同，答案不能直接相互替代。

### 不相关：100 对

1. 从现有基线聚类的不同簇中随机组合问题；
2. 要求两题不共享 Oracle/PLSQL 错误码；
3. 要求标题 Jaccard 相似度不高于 `0.02`；
4. 排除已经选择过的重复或相关问题对；
5. 使用随机种子 42，抽取 100 对。

这组用于构造简单负例，检验模型是否能够排除主题明显不同的问题。

### 标签可信度

| 标签 | 标签依据 | 当前状态 |
| --- | --- | --- |
| 重复 | 数据正文中的平台 `Possible Duplicate`链接 | 高可信正例 |
| 相关但不重复 | 同簇、共享关键词或错误码的机器辅助初审 | 待第二人复核 |
| 不相关 | 跨簇、无共享错误码、极低标题相似度 | 待第二人复核 |

因此，该数据可以用于当前实验和方法比较；若要作为正式金标准，应安排另一名成员
逐对复核两类负例，并记录标注一致率。

## 实验设置

- 特征：标题重复3次 + 正文 + 标签重复2次的TF-IDF
- 归一化：L2
- 聚类：球面KMeans，K=50
- 重复判断：同簇且余弦相似度 >= 0.55

### 实验范围

本次实验不是在全部 152,758 条问题上重新训练并评测，而是：

1. 从原始数据中选出 300 个问题对；
2. 提取这些问题对涉及的 542 个不同问题；
3. 只在这 542 个问题上重新构建 TF-IDF 特征；
4. 对 542 个问题执行 K=50 的球面 KMeans；
5. 在 300 个已标注问题对上计算指标。

因此，本报告结果属于“局部标注集验证结果”，用于比较方法和发现问题，不能直接
等同于全量 152,758 条数据上的最终线上效果。

### 阈值与数据划分

当前重复阈值固定为 `0.55`，相关阈值固定为 `0.15`。本次300对数据没有继续拆分
为验证集和测试集，也没有使用这300对执行系统化阈值搜索。

为避免未来调参造成测试集信息泄漏，后续应：

1. 固定随机种子，将300对分成验证集150对和测试集150对；
2. 只在验证集选择K值、相似度阈值和模型参数；
3. 参数固定后，仅在测试集报告一次最终指标；
4. 若需要更稳定的结果，可采用分层五折交叉验证。

当前指标应称为“固定阈值下的初步评测结果”，不应称为独立测试集上的最终性能。

### 类别分布与抽样偏差

测试集人为设置为重复、相关但不重复、不相关各100对，类别比例为 `1:1:1`。
这种平衡设计便于比较各类别，但与真实系统中的重复问题比例不同。

- 实际数据中重复问题通常远少于非重复问题；
- 平衡测试集上的Precision可能高于真实部署场景；
- 100个不相关样本属于跨簇低相似的简单负例，可能抬高Accuracy和Macro-F1；
- 100个相关但不重复样本用于补充困难负例，更能反映误报风险。

因此，报告应同时展示Precision/Recall/F1和各类别Support，不能只展示Accuracy。

## 评价指标定义

二分类中，仅“重复”记为正类，“相关但不重复”和“不相关”均记为负类。

\[
Precision=\frac{TP}{TP+FP}
\]

\[
Recall=\frac{TP}{TP+FN}
\]

\[
F1=\frac{2\times Precision\times Recall}{Precision+Recall}
\]

\[
CandidateRecall=
\frac{\text{被聚到同一簇的真实重复对}}
{\text{全部真实重复对}}
\]

Candidate Recall只评价聚类候选召回阶段，不受最终余弦阈值影响。Precision@K
表示按余弦相似度从高到低排序后，前K对中真实重复问题对的比例。

## 解释

Candidate Recall 衡量真实重复对被聚到同一簇的比例；最终 Recall 还会受到余弦
阈值影响。若 Candidate Recall 明显高于最终 Recall，主要损失来自相似度阈值；
若 Candidate Recall 本身较低，主要问题在文本表示或聚类阶段。

### 漏报来源拆解

100对真实重复问题中：

- 41对进入同一聚类，Candidate Recall为41%；
- 其中18对达到0.55阈值，被正确识别；
- 23对虽然进入同一簇，但相似度低于阈值；
- 59对被分到不同簇，在候选生成阶段直接丢失。

因此，82个FN主要由两个阶段造成：

| 漏报原因 | 数量 | 占真实重复对 |
| --- | ---: | ---: |
| 聚类拆分到不同簇 | 59 | 59% |
| 同簇但低于相似度阈值 | 23 | 23% |
| 成功识别 | 18 | 18% |

当前首要瓶颈是聚类候选召回，而不是单纯调整最终阈值。

## 局限性与后续工作

1. 两类负例仍是机器辅助初审，需要第二位标注者逐对复核；
2. 应统计两名标注者的一致率和Cohen's Kappa；
3. `Possible Duplicate`是正文保留的链接证据，不等同于完整官方关闭状态字段，
   因此称为“高可信重复正例”更准确；
4. 当前实验只覆盖542个问题，不代表全量数据上的最终效果；
5. 300对是人为平衡样本，Precision不能直接外推到真实重复比例；
6. 阈值尚未通过独立验证集选择，应先划分验证集和测试集；
7. 应绘制不同阈值下的Precision、Recall和F1曲线；
8. 应使用Bootstrap计算主要指标的95%置信区间；
9. 后续优先尝试Word2Vec/加权Word2Vec或句向量，提高Candidate Recall；
10. 最终方案应在全量聚类输出上重新运行，再使用独立测试集报告指标。
